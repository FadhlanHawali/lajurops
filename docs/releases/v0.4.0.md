**Search**: find any task by title or key from anywhere, even with a typo, and narrow it down as you type.
One database migration (016) runs automatically on start; no configuration changes.

## Search

- **Ctrl+K anywhere** (⌘K on a Mac), or the **Search** box at the top of the sidebar, opens the search palette
  over whatever you're doing. It searches every workspace you can see.
- **Titles and keys.** Words match task titles in any order. A key like `APP-55` (or just `55`) jumps to that
  task first.
- **Typos are fine.** `relase notes` still finds *Prepare release notes*, while unrelated words like "develop"
  don't match "deploy".
- **Know where it lives.** Results are grouped into **Projects**, **Daily tasks** and **Hourly tasks**, each
  with its key, highlighted title, path (`APP › Billing v3 › Release prep`), dates, environment and status.
  Open work ranks before done, then tasks closest to today.
- **Filters as you type**, shown as chips:

  | Filter | Means | Example |
  |---|---|---|
  | `@person` | assigned to someone (`@me` for you) | `@alice deploy` |
  | `#environment` | done in that environment | `deploy #prod` |
  | `is:open` / `is:done` | not done yet, or done | `is:open @me` |
  | `type:` | `project`, `daily` or `hourly` | `type:hourly #prod` |
  | `in:` | inside a project whose name contains this | `in:billing type:daily` |
  | `due:` | `today`, `tomorrow`, `this-week`, `last-week`, `next-week`, `this-month`, a month (`oct`) or a date | `deploy due:last-week` |

  A mistyped filter (`due:soon`) is flagged instead of silently ignored.
- **? in the footer** explains every filter with examples you can click to try.
- **Keyboard first:** ↑/↓ to move, Enter to open the task, Esc to close (it never closes a task dialog underneath).
- **Recently opened** tasks show up before you type (remembered in your browser).

## Fast on big data

Measured on 89,000 tasks across five workspaces:

| Search | Time |
|---|---|
| A task key | **10 ms** |
| Filters only (`@user7 #prod is:open`) | **27 ms** |
| A word (`deploy`), 40+ matches | **57 ms** |
| A typo (`deplyo`) | **80 ms** |

Typing waits 150 ms before searching, so results appear as you type.

## Notes

- Typo matching uses the `pg_trgm` extension that ships with Postgres; migration 016 enables it and adds an
  index. If your database user isn't allowed to enable it (some hosted databases), search still works, just
  without typo tolerance.
- New endpoint: `GET /api/search?q=&tz=` (or `?ids=a,b` for specific tasks); see the README.
