**Security and performance**: built with Go 1.27.1 and current dependencies, which clears every known
vulnerability in the server and roughly doubles API throughput. No migrations, no configuration changes.

## Security

`govulncheck` reported 39 vulnerabilities that the server's code actually reaches; it now reports none.
`npm audit` is clean as well.

- **Go 1.22.5 → 1.27.1** (end-of-life → current). Fixes HTTP request smuggling, auth headers leaking on
  cross-origin redirects, proxy bypass, and a batch of TLS, x509 and URL-parsing denial-of-service issues.
- **pgx v5.6.0 → v5.11.0**: SQL injection through placeholder confusion with `$$`-quoted strings (GO-2026-5004).
- **go-jose v4.0.2 → v4.1.5** (via go-oidc v3.21.0): a crafted token could panic sign-in checking (GO-2026-4945).
- **chi v5.1.0 → v5.3.2**: client IP spoofing through `X-Forwarded-For` in the logs (GO-2026-5775, GO-2026-5777).
- **x/net, x/oauth2, x/text** updated: proxy bypass, HTTP/2 and parser denial-of-service fixes.
- Web: `postcss-selector-parser` forced to 7.1.6 (GHSA-rj75-hqrm-r3gf); the built CSS is unchanged.

## Faster

Old and new builds measured side by side: same Postgres with 2,000 tasks, app limited to 2 CPUs and 512 MB.

| Workload | v0.4.0 | v0.4.1 |
|---|---|---|
| Reads, 32 users | 148 req/s, p95 509 ms | **342 req/s**, p95 191 ms |
| Reads, 128 users | 148 req/s, p99 2.2 s | **375 req/s**, p99 0.9 s |
| Writes, 32 users | 1,478 req/s, p95 62 ms | **3,018 req/s**, p95 16 ms |
| Peak memory under load | 204–288 MB | **87–113 MB** |

The gain comes from the pgx upgrade. Sign-in token checking costs the same as before (about 43 µs).
