**Runbooks** for releases and maintenance windows, short daily tasks committed automatically on Weekly Commitment,
and projects that stay open until someone closes them.
Four database migrations (012–015) run automatically on start; no configuration changes.

## Runbooks

- **A checklist with a plan.** Open an hourly task and build its runbook from sections you name (Preparation,
  Implementation, Verification, Rollback, or your own), each with steps that have a date, a start time and a
  duration. The header shows how many steps are done and the hours of work; overdue steps turn red.
- **Notes in Markdown.** Steps and sections take Markdown notes; commands in code blocks get a **Copy** button
  (without the trailing newline, so it's safe to paste into a terminal).
- **A step can be a daily task.** Add a step as a **Daily task** over a range of days, e.g. preparing the day
  before a release. It gets the step's title and notes, the release's project, environment and owners, and
  the release waits for it. Ticking the step completes the task and the other way round. Turn an existing step
  into a task, or back into a plain step, from its row.
- **Templates per workspace.** Save a runbook as a template and apply it to the next release: step times move
  with the task's start, and steps saved as daily tasks create new ones.
- **Just a warning.** Marking a task done with unticked steps shows a warning but doesn't block it. Board cards
  show `done/total` steps.
- **In backups.** Workspace export and import include runbooks, links to daily tasks and templates.
- Runbooks are for **hourly** tasks only.

## Weekly Commitment

- **Short daily tasks are automatic.** A daily task of at most 7 days, assigned to you, is committed in the week
  its last day falls in, like hourly tasks in the week they start. Longer or undated daily tasks are still
  picked by hand, and a task you picked stays in your order.
- **Daily and Hourly tabs** in *This week I will finish*: your picks and the automatic daily tasks in one tab,
  hourly tasks in the other.

## Heads up: behaviour changes

- **Projects are done only when you mark them done.** Progress still follows the tasks, but finishing the last one
  no longer closes the project: it shows *All tasks done · not closed yet* with a **Mark done** button. The
  project dialog has **Mark project done** and **Reopen project**. Projects already done stay done.
- **Weekly Commitment counts more.** Because short daily tasks are now automatic, past weeks' *last week kept*
  and the overdue list include them too.

## Faster

Measured with 30 people, 89,000 tasks and 218,000 runbook steps:

| | v0.2.1 | v0.3.0 |
|---|---|---|
| Open a 50,000-task workspace, all dates (server) | 1.83 s | **1.32 s** |
| Import a 10,000-task backup | 17.3 s | **3.2 s** |
| Calendar month, all workspaces | 284 ms | **213 ms** |
| A runbook (12 steps) | – | **5 ms** |
| Tick a step | – | **6 ms** |

Runbook step counts are stored on each task (kept current by the database) instead of counted on every list,
and import writes each table in one statement.

## API

New endpoints for runbooks and templates (see the README): `GET /api/tasks/{id}/runbook`, sections and steps
under `/api/runbook/...`, `POST /api/runbook/steps/{id}/task`, and `GET /api/workspaces/{id}/runbook-templates`.
Tasks carry `runbook_total` and `runbook_done`.
