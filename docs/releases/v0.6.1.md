**Outages explained**: when the database, the server or Keycloak can't be reached, LajurOps now says so
and reconnects by itself, instead of showing empty pages that still look usable. No migrations, no
configuration changes.

## The database is down

- A banner at the top, above any open dialog: **Can't connect to the database**. What's on screen may be
  out of date or empty, and changes won't be saved until it's back. **Retry now** is there too.
- It keeps checking, and when the database answers again it says **Connected again** and reloads what's on
  screen. No page refresh needed.
- The server checks the database every 3 seconds. While it's down, requests get "database unavailable"
  (HTTP 503) at once, and requests already waiting on it give up. New connections time out after 5 seconds.
- Dialogs opened during an outage show their error instead of a spinner that never stops.

| A frozen database | Before | Now |
|---|---|---|
| A request in flight | hung for 40 s or more | 503 after about 3 s |
| Later requests | hung the same way | 503 in about 3 ms |
| Banner shown | never | about 5 s after it froze |
| Back to normal | — | about 2 s after it answers |

## The server can't be reached

The same banner says **Can't reach the LajurOps server** when nothing answers (it may be restarting, or
the network is down), or when a proxy in front has no server to ask (502/504).

## Keycloak is down

You can keep working while your session is valid. After that:

- **Renewing the session** (Keycloak's 15-minute tokens) no longer sends the browser to Keycloak's address
  and the browser's "can't reach this page" error. The banner says **Can't reach the sign-in service
  (Keycloak)**, and turns into **Connected again** when it's back.
- **Opening or reloading the app** shows a **Sign-in is unavailable** page that keeps trying and opens the
  app once Keycloak answers. The same page covers a server that's unreachable at startup.
- **Sign in with Keycloak** says Keycloak isn't answering instead of leaving the app.
- **A restarted server** that can't fetch Keycloak's signing keys answers "sign-in service unavailable"
  (HTTP 503) instead of 401. Before, every request failed with a red "server rejected your sign-in" banner
  and a raw error.

`/readyz` still leaves Keycloak out on purpose: a Keycloak outage shouldn't take every replica out of the
load balancer while signed-in users can still work.

## Notes

- API clients: a database outage is now `503 {"code":"database_unavailable"}`, and unreachable Keycloak
  signing keys are `503 {"code":"auth_unavailable"}` (they were 500 and 401). A wrong `OIDC_JWKS_URL` also
  gives 503 now; the reason in the response and the server log still says which URL failed.
