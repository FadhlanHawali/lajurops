A performance release: LajurOps now stays responsive with tens of thousands of tasks in a workspace.
No database migrations and no configuration changes; just run the new image.

## Faster with large workspaces

We stress-tested workspaces of 1,000 to 50,000 tasks (89,000 in total). Times until a view is ready,
for a 50,000-task workspace:

| View | v0.1.0 | v0.1.1 |
|------|--------|--------|
| Timeline | 19.8 s, 907 MB memory | **0.9 s**, 23 MB |
| Board, all dates | 22 s, 743 MB memory | **1.5 s**, 52 MB |
| Board, this week | 2.5 s | **0.4 s** |
| Project board | 2.5 s | **0.6 s** |
| Calendar, week | 2.0 s | **1.1 s** |
| Calendar, all workspaces | 5.4 s | **2.3 s** |
| Week grid | 0.5 s | **0.13 s** |

What changed:

- **Timeline** loads only the time window around what you're looking at (sized by the zoom level) and
  loads more as you scroll towards either edge. Only the rows on screen are drawn.
- **Board**: the date filter is applied by the server, and columns show 100 cards at a time with
  **Show more**.
- **Project board** loads only the projects; each project's progress is counted by the server.
- **Task dialog**: the "waiting for / blocking" picker searches the server as you type (by title or key,
  e.g. `APP-12`) instead of loading every task in the workspace.
- **Calendar**: busy time slots show up to three events side by side, then "+N more".
- **Database**: LajurOps turns off PostgreSQL's JIT compiler for its connections. On larger databases
  it added 400 ms or more to some requests, for example the cross-workspace calendar (437 ms → 88 ms).
  A `jit` setting in `DATABASE_URL` still takes precedence.

## API

- `GET /api/tasks` has new options: `undated=open|all` (with `from`/`to`, also tasks without dates),
  `ancestors=true` (also the matches' parent projects and daily tasks) and `q`/`limit` (search by title
  or key, best match first). A date range now also matches tasks that only have an end date.
- New: `GET /api/workspaces/{id}/project-progress` returns done/total daily and hourly tasks per project.
