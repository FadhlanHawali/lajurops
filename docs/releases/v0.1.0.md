The first public release of **LajurOps**: open-source planning for ops teams. Projects, requests and
deployments on one timeline, across every environment, down to the hour.

> *Lajur* is Indonesian for "lane": every person, project and environment is a lane on the timeline.

## Highlights

### Plan work the way ops teams do it
- **Three task types, nested Project → Daily → Hourly.** Projects hold the big picture, daily tasks track
  requests and deliverables by date, and hourly tasks capture deployments, implementations and support
  windows with exact times. Daily and hourly tasks can also stand on their own.
- **Long and short projects**, grouped by **category** (KPI, Enhancement, Ad Hoc, or your own, with any
  colour). A project's status and progress come from its tasks, so nobody has to update them by hand.
- **Environments per project** (Dev → QA → Staging → Production, or whatever you use). Tasks say where the
  work happens, and a project's tasks are grouped by environment.
- **Dependencies**: "Deploy to Staging" waits for "Set up staging". Cycles are rejected, blocked cards say
  what they're waiting for, and the timeline flags work scheduled too early.
- **Multiple owners** per task, **Markdown comments** with a toolbar and preview, and the creation date
  on every item.

### See it from every angle
- **Board**: Kanban for daily and hourly work, plus a project board by category. Search and sort inside each
  column; filter by assignee, project, environment and date (this week by default). Finished projects fold
  away.
- **Timeline**: a Gantt chart that zooms from months down to **single hours**; drag to reschedule, drag edges
  to resize, with dependency arrows.
- **Calendar**: month, week, day and agenda views; drag to reschedule or select a slot to create a task.
- **Workload**: hours and tasks per person per week or month, with **parallel work counted once**, a
  drill-down per person, CSV export, and a **week grid** of people × days showing who has which hourly
  tasks.

### Run it for your team
- **Keycloak sign-in** (OIDC + PKCE) and in-app **user management**: create, disable and delete users, reset
  passwords, and sync people deleted in Keycloak.
- **Roles per workspace**: admins have full access; everyone else is an **editor** or **viewer** of each
  workspace, or doesn't see it at all. The server enforces it, and viewers get a read-only interface.
- **Backup and restore**: export a workspace to JSON and import it from a file or a URL.
- **One binary, one image**: the React frontend is embedded in the Go server. The Docker image is about
  23 MB, for linux/amd64 and linux/arm64.
- **Built for corporate networks**: clear sign-in diagnostics (issuer mismatch, proxies, clock skew),
  `NO_PROXY` defaults, and support for internal certificate authorities (`KEYCLOAK_CA_CERT`).

## Get started

The repository's `docker-compose.yml` runs LajurOps with Keycloak (a ready-made realm with demo users)
and PostgreSQL:

```bash
git clone https://github.com/FadhlanHawali/lajurops.git
cd lajurops
cp .env.example .env
docker compose pull app
docker compose up -d
```

Open http://localhost:8080 and sign in as **alice** (admin) or **bob** (member); their passwords are in
`deploy/keycloak/realm-lajurops.json`. Change them, and the other defaults in `.env`, before exposing the
stack. See the README for configuration, using an existing Keycloak, and production notes.
